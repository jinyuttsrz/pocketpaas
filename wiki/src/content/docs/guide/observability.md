平台的可观测能力由四部分组成：指标采样、就绪探针、告警中心、操作审计，另有一键诊断作为排障入口。

## 指标采样

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `METRICS_INTERVAL` | `5` | 应用资源采样间隔（秒） |
| `METRICS_KEEP` | `720` | 每个应用保留的采样条数 |
| `HOST_METRICS_INTERVAL` | `2` | 宿主机性能采样间隔（秒） |
| `HOST_METRICS_KEEP` | `90` | 宿主指标保留帧数（约 3 分钟滚动窗口） |
| `HOST_CONTAINER_INTERVAL` | `5` | 受管容器占用（CPU / 内存 / 网络）刷新间隔 |

前端据此绘制：

- 应用详情抽屉 → 「负载曲线」tab：该应用的 CPU / 内存曲线；多容器应用按服务分别采样，
  默认展示公开服务，可通过抽屉顶部的服务选择器切换；
- 「资源与节点」页：宿主 CPU / 内存 / 磁盘实时曲线、受管容器资源占用、端口区间用量。

指标接口支持 `?service=<服务名>` 过滤；不传时取公开服务，无服务记录的历史应用回退到应用整体采样。

## HTTP 就绪探针（四态）

| 状态 | 判定 | 处理 |
|---|---|---|
| `ready` | HTTP 状态码 < 500 | 视为可服务 |
| `degraded` | HTTP 状态码 ≥ 500 | **只展示，不重启**，避免重启风暴 |
| `unready` | 连接被拒 / 超时 | 计入连续失败次数，达阈值才触发重启 |
| `unknown` | 尚未探测或无法判断 | 仅展示 |

探活目标为 `127.0.0.1:{宿主端口}{HEALTH_HTTP_PATH}`，只针对公开服务；内部服务没有宿主端口。

:::note[自愈粒度是服务]
巡检线程按 `app_services` 逐服务检查容器并刷新服务状态。公开服务丢失或持续崩溃才会把应用置为
`failed`；内部服务（数据库、缓存等）异常只标记该服务 `failed`，不会因瞬时故障把整个应用永久判死。
:::

相关配置：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `ENABLE_HEALTH_WATCHDOG` | `true` | 自愈巡检总开关 |
| `HEALTH_CHECK_INTERVAL` | `15` | 巡检间隔（秒） |
| `ENABLE_HEALTH_HTTP` | `true` | HTTP 就绪探针开关 |
| `HEALTH_HTTP_PATH` | `/` | 探活路径 |
| `HEALTH_HTTP_TIMEOUT` | `2.0` | 单次探活超时（秒） |
| `HEALTH_HTTP_MAX_FAILS` | `3` | 连续失败多少次触发重启 |
| `HEALTH_MAX_RESTARTS` | `3` | 连续自动重启上限，超过则置 `failed` |

:::note[为什么 5xx 不触发重启]
应用自身返回 5xx 说明进程还在、只是业务出错，重启通常无效且会造成重启风暴。
只有**连接层**不可达才计入失败并重启。
:::

## 指标阈值告警中心

五类规则：

| 规则 | 配置项 | 默认阈值 |
|---|---|---|
| 宿主 CPU | `ALERT_CPU_PERCENT` | `85.0` |
| 宿主内存 | `ALERT_MEM_PERCENT` | `85.0` |
| 宿主磁盘 | `ALERT_DISK_PERCENT` | `90.0` |
| 应用自动重启 | `ALERT_RESTART_COUNT` | `3` |
| 应用失败 | — | 状态置 `failed` 时触发 |

状态流转：

```text
active（待处理） --手动确认--> acked（已确认，指标持续超限仅刷新观测值）
active / acked  --指标回落--> resolved（巡检自动置为已恢复）
```

:::tip[确认后不会重复打扰]
告警确认后，即使指标持续超限也不会反复产生新告警，只会刷新观测值；
指标回落后由巡检自动置 `resolved`。
:::

巡检开关与间隔：`ENABLE_ALERTS=true`、`ALERT_CHECK_INTERVAL=30`。

## 操作审计日志

覆盖 **25 个动作**：

- 认证：登录 / 注册 / 登出
- 应用：创建 / 构建 / 部署 / 停止 / 重启 / 回滚 / 单服务重启 / 配额 / 配置 / 源码 / 文件 / 诊断 / 健康探针 / Webhook 及其重置 / 销毁
- AI：状态分析 / 运维问答
- 用户：创建 / 更新 / 重置密码 / 删除

「审计日志」页提供动作字典与审计流水，普通用户按租户过滤，管理员可见全部。
接口为 `GET /api/audit/logs`（`limit ≤ 500`）与 `GET /api/audit/actions`。

## AI 运行分析

控制台「AI 助手」基于当前平台快照提供**只读**分析与问答：

- 数据源：宿主指标、应用与服务状态、最近部署、未消除告警、最近审计；
- 权限：普通用户只看到自己的应用与告警，宿主级告警仅管理员可见；
- 安全：不发送环境变量、Webhook 密钥、文件内容和完整日志；平台数据用随机 nonce 包裹，
  用户可控文本会清洗尖括号与控制字符；提示词文件明确要求忽略数据中的指令性文本；
- 只读：AI 不执行部署、重启、删除等操作，只给分析结论与操作建议；
- 配置：`AI_ENABLED`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_PROMPT_FILE` 等，
  见[配置参考](/reference/config/)；
- 接口：`GET /api/ai/health`、`POST /api/ai/analyze`、`POST /api/ai/chat`。

提示词默认位于 `backend/app/prompts/ai_system.md`，修改后按 mtime 自动生效，无需重启。
AI 回答支持 Markdown 渲染，HTML 会先转义，链接仅允许 http/https 与站内路径。

## 一键诊断

对单个应用执行 **8 项只读检查**：

| 检查项 | 关注点 |
|---|---|
| 应用状态 | 数据库中的状态是否与预期一致 |
| 源码目录 | `workspace/{app_id}/src` 是否存在且非空 |
| 镜像 | 应用镜像是否已构建 |
| 容器 | 容器是否存在、是否运行；多服务 compose 逐服务分组检查 |
| 宿主端口 | 分配的端口是否被占用 / 是否可连 |
| 反向代理路由 | `paas-{id}.conf` 是否生成且 `listen` 正确 |
| 最近部署 | 最近一次部署记录与错误信息 |
| 资源配额 | 配额设置是否合理 |

单项结果为 `ok` / `warn` / `fail` / `skip`，全部只读，不产生副作用。
多容器应用的服务容器会以「服务 <名称>（公开 / 内部）」逐条展示检查结果。
适合作为「应用打不开」时的第一条排查命令。
